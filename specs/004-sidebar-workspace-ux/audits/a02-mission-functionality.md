## Method and evidence

- [Observation harness](probes/a01-a02.mjs) and durable results: [drafts](evidence/efcd523-drafts.json), [missions](evidence/efcd523-missions.json), [ideas](evidence/efcd523-ideas.json).
- UI actions create/edit/confirm missions. Setup hooks create real reviewed fixture profiles, approve temporary folders and launch fake echo sessions through normal contracts. Authoritative readbacks use missionComposer.getDraft and missions.detail/list; lifecycle checks use liveSessions. These setup/readback operations are explicitly not substitutes for UI actions.
- The normal and failure draft scenarios close and reopen the isolated app. Mission deletion also receives a restart readback. Real provider autonomy, external side effects and paid provider runs are not exercised.
- Five existing E2E specs passed: mission-composer, mission-focus-workspace, supervisor-mission and accessibility (28 tests, 2.4m), plus repo-idea-generation (4 tests, 12.4s). Tests establish their named scenarios only. Historical screenshots/findings remain in [the original report](missions.md) and [merge reconciliation](main-merge-reconciliation.md).

## Findings: updated severity and evidence

All improvements are proposed and not implemented. Existing MIS IDs retain their meaning.

- **MIS-002 — High, confirmed data loss.** D03 waits beyond the 800ms save window after New mission: stored value remains the older objective. D05–06 induce storage failure, navigate to Agents with no dialog, restart, and recover only the older value. Normal D04 succeeds. Unify every exit around a save result; leave failed edits mounted/recoverable until the user explicitly decides otherwise. FR-005/018; US2.2–3.
- **MIS-003 — High, confirmed impossible edit and weak repair.** The UI accepts a different model for a live session and persists it; Review rejects it with generic envelope-changed copy and creates no mission. Expose existing-session values as fixed; offer Switch to new session before editing. Map the error to the exact field. FR-006/011/016–017; US3.1, US7.1–3.
- **MIS-004 — High, shared-mode change can strand supervisor access.** Saved mode changes apply to the folder and therefore supervisor. Returning the worker to another folder does not undo the supervisor mode. The review hold is correct, but its Access link has no direct supervisor control. Group access by folder and list all affected members, including supervisor. FR-006/013; US3.2.
- **MIS-006 — Medium, stale ideas reproduced.** Selecting repo B leaves repo A ideas selectable. Pick/readback retains the old objective/proof but no repo association. Invalidate suggestions on input change, retain visible source context, and accurately label provider/default selection. FR-010; US5.5.
- **MIS-009 — Medium, friction rather than failed normal persistence.** Successful close/readback/restart passes. The unnecessary second close remains a UX proposal; do not claim normal close loses data. Show save status and close directly after success, retaining explicit failure choices. FR-009; US5.2.
- **MIS-015 — Medium, draft-cap recovery has no normal delete path.** At 20 drafts, creation is correctly blocked and all 20 remain available. The error says to complete or delete one, but normal rows/composer have no discard action. Provide a Manage drafts action and confirmed discard; do not remove the storage limit just to hide the problem. FR-008/011/018; US4.1, US7.3.

MIS-001/007/008/010/011/012/013/014 remain as documented previously. MIS-005 uses the unchanged app baseline from the retained PR #29 screenshot. A01 adds the narrow 20-draft layout condition (NAV-004). Source-only issues are not promoted by passing broad tests. Two further hypotheses remain pending: an in-flight save may clear newer dirty state, and unsubmitted ListEditor text may be lost on navigation. Neither is reported as reproduced here.

## Proposed interaction design

1. **Entry and navigation:** open the chosen view from any destination; keep the sidebar, main content and context synchronized. Preserve edits before switching.
2. **Draft management:** show a short identity and Saved/Saving state; add a normal management menu and a cap-recovery path. Close once after successful save. Failed saves offer Retry, Keep editing, or an explicit unsaved exit.
3. **Crew and access:** use Existing session / New session as the visible choice. Existing launch values are read-only. Group folder permissions with names of all affected crew members. Review errors link to the exact editable setting.
4. **Ideas:** changing repo/provider makes old suggestions unavailable until refreshed; show source repo and provider; keep chosen text editable without implying mission approval.
5. **Review and lifecycle:** keep the final approval action in the common action area. Land on the mission overview after success. Explain that pausing assignment does not stop attached sessions; keep process Stop distinct. Preserve revision, cancellation, deletion and unknown-effect confirmation rules that already work.
