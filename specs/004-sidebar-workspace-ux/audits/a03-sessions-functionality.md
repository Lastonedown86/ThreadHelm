## Proposed interaction design

1. Open Sessions into a visible scope: All sessions by default, with an explicit Selected mission filter and count. Opening a mission's terminal may select that scope; global Sessions remains a reliable route back.
2. Put session identity and live controls first. Keep launch setup and directed coordination discoverable in secondary disclosures. Use one consistent active/ended inventory, with named selection and predictable keyboard movement.
3. On successful launch, reveal the exact new session and its terminal. On expiration, offer Refresh review in place and keep the requested settings. Never infer launch authority from retained input alone.
4. Preserve the working Interrupt -> Stop -> separately confirmed Force stop sequence. Explain observed outcomes and retain exact provider/folder/ID identity.
5. Keep recovery records distinct from live processes. Review the named old session, dismiss/acknowledge the record, or start separately reviewed replacement work. Reconcile Dismiss wording with A07 because it changes durable state rather than hiding a temporary banner.

Recommended first slice: SES-001, since it affects access to live session controls and newly launched work. Reconcile it with A01 navigation and A02 mission scoping before planning. SES-002/003 can then share an inventory redesign; SES-004 is an independent repair flow. This is a proposal, not implementation authorization.

## Acceptance summary and handoff

- Visual/interaction: observed inventory, identity, scope and markup inconsistencies; inspected screenshots. Existing sampled keyboard/reflow checks pass, but do not establish complete accessibility acceptance.
- Logic: exact-target process guards and sampled recovery/coordination rules hold. Mission scope and ended disclosure logic have confirmed problems. Delayed conversation selection remains source-only.
- Functionality: real isolated Electron UI exercised; saved session state, lifecycle events, Job Object/PID evidence and restart behavior checked independently. Fixture process-control success does not establish real-provider autonomy.
- Missing: large session/recovery inventories, full narrow/200% matrix, every runtime permission/limit combination, terminal import/stream/backpressure failures, delayed selection races, pending-operation Escape, all recovery classifications, direct native window-close gesture and all coordination pause/failure variants. A07/A08 own complete queue and setup audits; Feature 002/003 authority/release gates remain open.
- Validation: fresh desktop build passed; 5 launch/multi-session/stop/recovery E2E tests passed (57.6s), plus 16 coordination/terminal/accessibility tests (1.4m), total 21 selected tests. Full suite and real providers were not run. Both direct observation scenarios completed (2.3m), recording 11 observations. Completion does not mark the findings fixed.
