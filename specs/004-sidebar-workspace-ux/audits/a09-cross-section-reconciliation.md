## Proposed interaction design and recommended sequence

1. **Next: MIS-003, existing-session runtime truth.** Reproduce M01 on current main before editing. Existing workers show their actual fixed runtime values and session identity; offer an explicit switch to a new session for editable runtime settings. Keep authoritative review checks and map any stale-session mismatch to the exact worker. Verify saved draft/reopen and zero unintended missions/processes, including a session changed or ended after selection. FR-006/011/016/017. This removes an impossible control with high impact without combining it with access redesign.
2. **MIS-004, folder access clarity.** Present access by approved folder, list every affected member including supervisor, and offer direct repair from Review. Preserve folder-level authority and confirmation. Revalidate shared-folder moves and saved access before implementing. FR-006/013; a separate design/implementation slice.
3. **SES-004, then TPL-002: consistent review recovery.** An expired or consumed review disables its old confirmation and exposes a fresh review preserving valid input. Reconfirm the current facts; never automatically launch/delete or relax main validation. Template dependency repair remains operation-specific. FR-010/011/018.
4. **SES-002/003 and residual SES-005:** agree one inventory policy and meaningful workspace/session names, keyboard selection and unique ID relationships. Keep execution independent of visual filtering. FR-007/008/009/012.
5. **Draft identity/capacity and remaining matrices:** MIS-007/015, NAV-004 and TPL-001 need bounded inventories, meaningful identity and exact discard recovery, respecting separate draft types. Recheck AGT-003 and embedded setup layout before new reflow changes.

Shared conventions are truthful identity/scope, stable selection, valid error recovery, one main landmark, explicit review of consequences and outcomes verified independently of UI copy. Sections may retain justified differences: Memory's temporary reading list is not saved publication; Attention lists recovery records; Settings recon proposals are temporary until imported into Agents.

ProviderReadiness and WorkspacePanel are also rendered inside Sessions. SET-003 recheck/lifetime component changes are shared, while SET-004 CSS is scoped to `.guided-setup`. Therefore Settings layout acceptance does **not** establish Sessions setup layout acceptance. This is a verification gap, not an observed new overflow defect.
